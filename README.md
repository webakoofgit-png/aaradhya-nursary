# Green Haven Emporium

Create a complete, premium, modern, multi-page e-commerce website for an Indian Plant Nursery business.

The website will serve two types of customers:

1. Retail Customers – B2C

2. Wholesale Customers – B2B

The website should take design inspiration from:

https://theaffordableorganicstore.com/

Do not copy the reference website exactly. Create a unique, professional and premium nursery brand design with a similar user-friendly shopping experience.

IMPORTANT:

Generate the complete frontend website in one attempt.

Do not create an admin panel or backend at this stage.

Use realistic demo products, content and properly linked pages.

Do not leave any empty page, broken button or placeholder section.

## B2B wholesale system

The B2B workflow uses TanStack Start server functions and a private SQLite database at
`.data/verdant.sqlite`. The database and uploaded customer documents are excluded from source control.

Key routes:

- `/wholesale/register` - multi-step buyer registration and document upload
- `/wholesale/login` - approval-gated customer login
- `/wholesale/dashboard` - protected catalogue and quotation workspace
- `/admin/login` - administrator login
- `/admin` - customer, quotation, product, notification and settings management

Set these environment variables before production deployment:

```bash
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=use-a-long-unique-password
PUBLIC_APP_URL=https://your-domain.example
PASSWORD_RESET_WEBHOOK_URL=https://your-email-service.example/reset-hook
```

For local development only, the first database bootstrap uses `admin@verdantroots.in` and
`Admin@12345` when those variables are absent. Set production values before the database is first
created. Persist and back up the `.data` directory on the deployment target.

Product CSV imports use this header row:

```text
sku,slug,name,category,description,image,retail_price,wholesale_price,gst_rate,minimum_quantity,stock,active,featured
```

Use `true`/`false` or `1`/`0` for `active` and `featured`. Images uploaded through the admin product
editor are stored in the protected product-images table and returned only through the approved
wholesale catalogue server function.
